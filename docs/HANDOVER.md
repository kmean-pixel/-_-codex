# 인계서 — 원장실 PC 정기 점검·최적화 자동화 시스템

> 이 문서는 **Claude Code 웹(원격 컨테이너) 세션에서 작업하다 중단하고, 사용자 본인 PC의 Claude Code 로컬 세션으로 인계**하기 위해 작성되었습니다.
> 작성일: 2026-09-15 / 브랜치: `claude/computer-maintenance-automation-0qpuhc`

---

## 0. 한 줄 요약

원장실 PC(Windows)를 **주간/월간/2개월 주기로 스스로 점검·정리**하고,
**자동으로 되는 것은 자동으로**, **관리자 개입이 꼭 필요한 것은 미리 알림**을 주는 시스템을 구축한다.
결과는 **반응형 HTML 대시보드**로 보고, 일정은 **구글 캘린더 + 예약 트리거**로 굴린다.

## 1. 사용자 원 지시사항 (원문 요지)

1. 유튜브 영상 2개를 **영상 시청(watch) 스킬로 분석**할 것
   - https://youtu.be/rat6VoqbsvQ
   - https://youtu.be/jt1Mx0alhzo
2. **이 두 영상만으로 판단하지 말고**, 오픈소스·인터넷 리서치를 **리서치 스킬**로 별도 수행해 교차검증할 것
3. 기준 PC는 **원장실 컴퓨터**. (다른 PC로도 확장 가능해야 하지만 1차 기준은 원장실 PC)
4. 윈도우 속도 관련해서 **"효과 있는 것"과 "굳이 안 해도 되는 불필요한 것"을 정리**할 것
5. 윈도우뿐 아니라 **부팅 등 컴퓨터 전반**을 주기적으로 점검
6. **주기: 1주 / 1개월 / 2개월** 단위로 계속 체크하는 **시스템**을 만들 것
7. **예약 시스템**을 만들어 자동으로 진행되게 할 것
   - 자동으로 할 것 → **구글 캘린더에 등록**해두고 자동 실행
   - **내가 수동으로 해야 하는 것** → 따로 정리해서 같이 제공
8. 결과물은 **가독성 있는 리액티브 HTML**로 만들 것
9. 사용자의 PC 사용 패턴에 **큰 지장이 없는 선**에서 진행
10. 주기적으로 점검하고, **확인(컨펌) 받아야 할 것은 받고**, 나머지는 **알아서 스케줄대로** 진행
11. 계속 쓰다 보면 **새 프로그램이 또 깔리므로**, 그런 변화를 감안해 **스스로 반복 점검**하게 할 것
12. 스스로 못 하는 것(관리자 권한 필요 / 물리적 작업)은 **미리 알림**을 주고, **안 했을 때도 재알림**할 것
13. 시간이 걸리더라도 **차분하게** 제대로 구축할 것

## 2. 이 세션에서 막힌 지점 (= 인계하는 이유)

| 막힌 것 | 상세 | 로컬 세션에서 해결되는가 |
|---|---|---|
| **유튜브 영상 시청 불가** | 원격 컨테이너의 조직 이그레스 정책이 `youtube.com`을 **403 차단**. 우회는 정책 위반이라 시도하지 않음. | ✅ 로컬 + 영상 시청 스킬로 해결 |
| **영상 시청 스킬 없음** | 이 세션에 YouTube/transcript 스킬이 설치되어 있지 않음 (`SearchSkills` 결과 0건) | ✅ 사용자가 직접 스킬 설치 예정 |
| **리서치 스킬 없음** | 전용 research/deep-research 스킬 없음. `WebSearch`(요약형)로 대체 수행함 | ✅ 스킬 설치 시 훨씬 정밀 |
| **외부 웹사이트 대부분 차단** | `learn.microsoft.com`, `support.microsoft.com`, `xda-developers.com`, `tweaktown.com`, `wikipedia.org` 전부 **CONNECT 403**. 접근 가능한 건 `github.com` / `raw.githubusercontent.com` 정도 | ✅ 로컬은 제약 없음 |
| **원장실 PC에 직접 접근 불가** | 원격 리눅스 컨테이너라 실제 Windows PC 상태를 읽을 수 없음. 모든 스크립트가 "가정 기반"이 됨 | ✅ **로컬에서 하면 실제 PC 상태를 읽고 맞춤 설계 가능 (가장 큰 이득)** |

> **결론:** 이 작업은 원격보다 **사용자 PC의 로컬 Claude Code 세션에서 하는 게 압도적으로 유리**합니다.
> 실제 설치된 앱 목록, 시작프로그램, 디스크 상태, 부팅 시간을 **직접 측정**해서 맞춤 설계할 수 있기 때문입니다.

## 3. 이미 확정된 사용자 결정사항 (재질문 불필요)

새 세션에서 **다시 묻지 말고 그대로 적용**하면 되는 항목입니다.

| 항목 | 결정 | 설계 반영 |
|---|---|---|
| **자동 점검 실행 시간** | **진료 종료 후 19:00경** | 작업 스케줄러 트리거를 19:00대로. 단 PC를 끄고 퇴근할 수 있으므로 `StartWhenAvailable`(놓친 작업은 다음 부팅 시 실행) 필수 |
| **관리자 권한** | **사용자 계정이 관리자임** | SYSTEM/최고 권한 작업 등록 가능 → 업데이트·디스크검사·정리까지 자동화 범위 넓음 |
| **알림 경로** | ① **PC 화면 토스트 알림 + 로컬 HTML 리포트**, ② **구글 캘린더 일정 + 알림** | Gmail 리포트는 **미선택**. 굳이 넣지 말 것 |
| **기준 PC** | **원장실 PC** (다른 PC는 나중에 확장) | 설정을 프로파일로 분리해 다른 PC 추가 가능하게 |

## 4. 이 세션에서 이미 확보한 리서치 결과 (재활용 권장)

`WebSearch`로 교차검증한 내용입니다. **새 세션에서 0부터 다시 할 필요는 없고, 이걸 출발점으로 검증·보강**하면 됩니다.
(단, 아래는 검색 엔진의 요약을 거친 2차 정보이므로 **1차 출처 원문 확인이 남아 있음** — 6장 참고)

### 4-1. ✅ 효과 있음 / 해야 하는 것

| 항목 | 근거 요지 |
|---|---|
| **시작프로그램 정리** | Task Manager가 영향도를 High/Medium/Low로 분류. High = CPU 1초 초과 또는 디스크 3MB 초과. 불필요한 시작프로그램 제거 시 부팅 30~60초 단축 사례. Autoruns(MS 공식)는 작업관리자에 안 보이는 항목까지 관리 |
| **Windows Update 최신 유지** | 보안 + 안정성의 기본. 드라이버도 MS 검증본이 여기로 옴 |
| **드라이버는 Windows Update 또는 제조사 유틸(Dell Command Update, Lenovo System Update, HP Support Assistant)로만** | 서드파티 드라이버 업데이터는 **스케어웨어/그레이웨어**로 분류됨. 비공식 크라우드소싱 DB에서 드라이버를 끌어와 불안정·악성 번들 위험 |
| **Storage Sense(저장 공간 센스) 활성화** | 임시 파일·휴지통 자동 정리. 기본값 꺼짐 → 켜야 함. 단 **다운로드 폴더 정리는 기본 끔 상태로 두는 게 안전** |
| **Optimize Drives(드라이브 최적화) 자동 일정 유지** | Windows가 SSD면 TRIM/retrim, HDD면 조각모음을 **알아서 구분해서** 주간 실행. 끄지 말고 켜둘 것 |
| **Defender 정기 검사** | 주간 빠른 검사 + 월간 전체 검사 |
| **SMART 디스크 건강 모니터링** | CrystalDiskInfo / `smartctl` / `Get-StorageReliabilityCounter`. **health% 수치보다 추세가 중요** — Reallocated Sector 증가, 온도(상시 60°C 초과 경고), Total Host Writes 확인. "주의(Caution)" 뜨면 최적화 말고 **백업부터** |
| **DISM → SFC 순서로 월 1회 예방 점검** | 반드시 **DISM 먼저, SFC 나중**. DISM이 이미지(WinSxS)를 고치고 SFC가 그 이미지로 시스템 파일을 복구하므로 순서가 뒤바뀌면 SFC가 계속 실패. 대형 업데이트(24H2/25H2 등) 직후에도 권장 |
| **3-2-1 백업** | 사본 3개 / 매체 2종 / 오프사이트 1개. OneDrive(클라우드) + File History(외장) + 분기 1회 시스템 이미지 조합. **OneDrive 동기화만으로는 백업이 아님** |
| **먼지 청소** | 3~6개월 주기. 필터는 월 1회 점검, 내부 심층 청소는 6개월 |
| **BIOS/펌웨어** | 매 버전 따라갈 필요 없음. **6개월에 한 번 확인** 정도 |
| **서멀 그리스** | 사무용 PC는 **3~5년**. 시간보다 **온도 기준** — 기준치 대비 10°C 이상 상승 시 교체 |
| **Windows 10 → 11 전환 확인** | Windows 10은 **2025-10-14 지원 종료**. ESU로 2027-10-12까지 연장 가능하나 임시방편. 원장실 PC가 아직 Win10이면 **최우선 과제** |

### 4-2. ❌ 무의미하거나 위험 — 하지 말 것 (사용자가 특히 궁금해한 부분)

| 하지 말 것 | 이유 |
|---|---|
| **레지스트리 클리너** | Microsoft가 **공식적으로 지원하지 않음**. 실제로 쓰이는 항목을 지워 앱 크래시·복구 불가 부팅 실패까지 유발 가능. 속도 향상 효과는 **없음** |
| **SSD 조각모음** | SSD에 조각모음은 **수명만 깎음**. 올바른 동작은 TRIM이고 Windows가 이미 자동 수행 |
| **RAM 클리너 / 메모리 최적화 앱** | 캐시를 강제로 비우면 오히려 **다시 읽느라 느려짐**. 현대 Windows 메모리 관리를 방해 |
| **서드파티 드라이버 업데이터** | 위 4-1 참고. 스케어웨어 |
| **무분별한 서비스 비활성화** | 일괄 disable 목록은 **Windows Update·보안 기능을 깨뜨림**. 그나마 안전한 건 하드웨어 의존 서비스(프린터 스풀러, 블루투스, 생체인식, Xbox 등) — 그것도 **해당 하드웨어를 안 쓸 때만** |
| **가상메모리(페이징파일) 수동 고정 / 비활성화** | 일부 프로그램이 **아예 실행되지 않거나** 메모리 부족 오류. 덤프 생성도 불가. **자동 관리가 정답** |
| **Ultimate Performance 전원 계획 상시 사용** | 벤치마크 이득 **2~5% 수준**, 일반 사무·웹 작업은 **체감 거의 0**. 대신 **발열·전력 소비만 증가**. 고성능 워크스테이션 전용 |
| **시각 효과 전부 끄기** | 현대 GPU에선 체감 이득 미미. (단, **구형 저사양 PC라면 의미 있음** — 원장실 PC 사양 확인 후 판단) |
| **원클릭 "최적화 프로그램"** | 대부분 플라시보 + 번들웨어. Microsoft PC Manager(공식)조차 **기존 Windows 기능의 편의 레이어일 뿐** 새로운 성능 향상은 없음 |
| **디블로트 스크립트 무분별 적용** | WinUtil(Chris Titus), Win11Debloat, O&O ShutUp10++ 등은 **"권장 설정"만** 쓸 것. 고급 토글 전부 끄면 Windows 보안 GUI 접근 불가 등 사례 있음. **반드시 복원 지점 생성 후 적용** |
| **빠른 시작(Fast Startup)** | **조건부**. MS 기본값은 켬. 최신 NVMe에선 단축 효과가 몇 초 수준으로 미미. **부팅 문제·업데이트 미적용·듀얼부팅 이슈가 있으면 끄는 게 나음** → 원장실 PC 실측 후 판단 |

### 4-3. 참고한 오픈소스 / 공식 도구

- **winget** (Microsoft 공식 패키지 관리자) — `winget upgrade --all --silent --accept-package-agreements --accept-source-agreements`. 앱 일괄 최신화 자동화의 핵심
- **Sysinternals Autoruns** (Microsoft 공식) — 숨은 자동 실행 항목 관리
- **Win11Debloat** (github.com/Raphire/Win11Debloat) — PowerShell, 설치 불필요, CLI 파라미터 지원, 설정 export/import 가능
- **WinUtil** (Chris Titus Tech) — 적용 전 **복원 지점 자동 생성**, 모든 변경 되돌리기 가능
- **O&O ShutUp10++** — 프라이버시/텔레메트리. "권장 설정"만 적용
- **CrystalDiskInfo** — SMART 모니터링
- **Microsoft PC Manager** — 공식이지만 신규 기능은 없음 (선택)

## 5. 이 세션에서 설계했던 아키텍처 (그대로 이어가도 좋음)

### 5-1. 디렉터리 구조 (제안)

```
scripts/
  config/tasks.json          ★ 단일 정보원(Single Source of Truth)
                               점검 항목 카탈로그. PowerShell 엔진과 HTML 대시보드가
                               같은 파일을 읽어 항상 동기화됨
  Install-Maintenance.ps1    작업 스케줄러 등록 / 폴더 생성 / 최초 스냅샷
  Uninstall-Maintenance.ps1  전체 제거(롤백)
  Invoke-PCMaintenance.ps1   메인 엔진. -Cycle Weekly|Monthly|Bimonthly
  modules/
    Checks.psm1              개별 점검 함수
    Report.psm1              HTML/JSON 리포트 생성
    Notify.psm1              Windows 토스트 알림
dashboard/
  index.html                 반응형 HTML 대시보드
docs/
  HANDOVER.md                (이 문서)
  PROMPT.md                  새 세션에 붙여넣을 요청문
```

### 5-2. `tasks.json` 스키마 (핵심 아이디어)

점검 항목 하나하나를 데이터로 정의하고, 실행 엔진과 대시보드가 **같은 데이터를 공유**하게 한다.
항목을 추가할 때 스크립트와 HTML을 따로 고칠 필요가 없어진다.

```jsonc
{
  "id": "MO-SNAPSHOT-APPS",
  "title": "설치된 앱 목록 스냅샷 + 변화 감지",
  "cycle": "monthly",              // weekly | monthly | bimonthly
  "mode": "auto",                  // auto(완전자동) | semi(자동실행+사용자확인) | manual(수동전용)
  "category": "변화감지",           // 보안 | 성능 | 저장공간 | 하드웨어 | 백업 | 변화감지
  "requiresAdmin": true,
  "impact": "high",
  "minutes": 2,
  "why": "쓰다 보면 모르는 사이 프로그램이 새로 깔림. 지난 스냅샷과 비교해 신규 설치 항목만 보고",
  "evidence": "사용자 요구사항 11번 / 시작프로그램 영향도 리서치",
  "action": "Invoke-AppSnapshot",  // auto인 경우 실행할 함수
  "steps": [],                     // manual인 경우 사용자가 따라 할 단계
  "risk": null
}
```

### 5-3. 자동/수동 분리 원칙

- **auto**: 스크립트가 끝까지 처리. 결과만 리포트 (예: 업데이트, 임시파일 정리, Defender 검사, 스냅샷 비교)
- **semi**: 스크립트가 **조사·제안까지만** 하고 실제 삭제/변경은 사용자 승인 후 (예: 새로 깔린 앱 제거, 시작프로그램 끄기)
  → **"컨펌 받아야 할 것은 받고"** 요구사항에 해당
- **manual**: 물리적 작업이거나 판단이 필요해 자동화 불가 (예: 먼지 청소, 외장 백업 드라이브 연결, BIOS 업데이트)
  → **캘린더 일정 + 토스트 알림**으로 미리 알리고, **미이행 시 재알림**

### 5-4. 3단 레이어 (사용자 요구 "예약 시스템")

| 레이어 | 역할 | 구현 |
|---|---|---|
| **A. PC 로컬 자동화** | 실제 점검·정리 실행 | Windows 작업 스케줄러 + PowerShell. 19:00 트리거, `StartWhenAvailable` |
| **B. 구글 캘린더** | 일정 가시화 + 수동 작업 알림 | 주간/월간/2개월 반복 일정. 설명란에 체크리스트 |
| **C. Claude 예약 트리거(Routine)** | 미이행 감지·재알림·리포트 해석 | `create_trigger`로 주기 트리거. 리포트를 읽고 "이번엔 이게 필요하다" 판단 |

### 5-5. 미이행 재알림 설계

각 점검 실행 시 `state.json`에 `lastRunAt` 기록 →
다음 주기 트리거가 돌 때 **기한 초과된 manual 항목**을 찾아 토스트 + 캘린더로 **재알림**.
(사용자 요구 12번: "안 했을 때도 이거 이거 해야 된다고 알려주고")

### 6-1. 반드시 해야 할 것 (이 세션에서 못 한 것)

1. **유튜브 영상 2개 실제 시청·분석** ← 최우선
   - https://youtu.be/rat6VoqbsvQ — **이 세션에선 제목조차 식별 실패**
   - https://youtu.be/jt1Mx0alhzo — 제목만 확인됨:

     → **"4가지 방법"이 정확히 무엇인지 확인 필요**
   - 영상이 주장하는 항목을 하나씩 뽑아 4-1 / 4-2 분류표에 대조할 것

2. **1차 출처 원문 확인** (이 세션은 검색 요약만 봄 — 원문 접근 차단)
   - Microsoft 공식: 레지스트리 클리너 미지원 정책, Storage Sense, Optimize-Volume, Fast Startup 권장사항
   - Sysinternals Autoruns 공식 문서
   - Windows 10 EOL / ESU / 25H2 업그레이드 경로 공식 안내

3. **원장실 PC 실측** ← 로컬 세션의 가장 큰 이득
   - Windows 버전 / 빌드 (`winver`, `Get-ComputerInfo`)
   - CPU / RAM / 디스크 종류(SSD·NVMe·HDD) 및 여유 공간
   - 현재 시작프로그램 목록과 영향도
   - 현재 부팅 시간 (이벤트 로그 `Diagnostics-Performance` ID 100)
   - SMART 상태 (`Get-PhysicalDisk`, `Get-StorageReliabilityCounter`)
   - 설치된 앱 전체 목록 (기준 스냅샷)
   - 데스크톱인지 노트북인지 (배터리 리포트 필요 여부)
   - → **실측 결과에 따라 "시각 효과 끄기", "빠른 시작 끄기" 같은 조건부 항목의 답이 달라짐**

### 6-2. 추가로 조사하면 좋은 것

- 원장실 PC에서 **실제로 쓰는 업무 프로그램**(전자차트/EMR 등)과 최적화 작업의 충돌 여부
  → 의료용 소프트웨어는 특정 서비스·구버전 런타임에 의존하는 경우가 많아 **디블로트 시 주의** 필요
- Windows 작업 스케줄러에서 **PowerShell 스크립트 서명 / 실행 정책** 우회 없이 안전하게 돌리는 방법
- Windows 토스트 알림을 스크립트에서 띄우는 최신 권장 방식 (BurntToast 모듈 등)
- 구글 캘린더 반복 일정의 **"2개월마다"** 표현 방식 (RRULE `FREQ=MONTHLY;INTERVAL=2`)
